TCP/IP: El Viaje de un Paquete

20 de Abril, 2026  |  TCP/IP Redes SOC Fundamentos

Antes de detectar una intrusión, un analista SOC necesita entender cómo viajan los datos. TCP/IP no es solo un protocolo — es el lenguaje universal de Internet. Este post convierte esa teoría en algo visual e interactivo: haz clic, mueve sliders, observa.

Las 4 capas del modelo TCP/IP

Imagina que mandas una carta al extranjero: escribes el contenido (Aplicación), la metes en un sobre con número de tracking (Transporte), el sobre lleva la dirección completa (Internet), y el cartero la lleva de buzón en buzón (Enlace). Cada capa solo habla con su par en el otro extremo.

Perspectiva SOC: Cada capa deja huellas distintas. Un SIEM correlaciona desde el payload HTTP (capa Aplicación) hasta la MAC de origen (capa Enlace). Saber qué dato vive en qué capa determina qué puedes detectar y con qué herramienta.

Three-Way Handshake: Cómo nace una conexión TCP

Antes de transferir un byte de datos, TCP sincroniza los números de secuencia entre cliente y servidor con 3 mensajes. Estos números garantizan orden y detección de pérdidas.

✓ Conexión establecida — listo para transmitir datos
Presiona "Siguiente paso" para iniciar el handshake.
SYN Flood Attack: Un atacante envía miles de SYN sin completar el handshake. El servidor reserva memoria por cada conexión "a medias" hasta agotarla (DoS). Señal en SIEM: alta tasa de SYN sin ACK correspondiente desde una misma IP.

Control de Flujo: La Ventana Deslizante

TCP no espera confirmación de cada paquete — sería lentísimo. Usa una ventana deslizante: el emisor mantiene hasta N paquetes "en vuelo". El receptor ajusta ese N según su buffer disponible.

Relevancia SOC: Una ventana TCP atascada en 0 (tcp.window_size == 0) puede indicar un receptor saturado, un ataque DoS en curso o un host comprometido consumiendo recursos. Wireshark y Zeek reportan este campo en cada captura.

Enrutamiento: Cómo los paquetes encuentran su camino

Cada router tiene una tabla de rutas. Al llegar un paquete, busca la entrada con el prefijo más específico que coincida — Longest Prefix Match. El paquete salta de router en router y el TTL decrece en cada salto.

Disminuye 1 en cada router. Si llega a 0, el paquete se descarta y se responde con ICMP "Time Exceeded" — la base de traceroute.

TTL en seguridad: El TTL inicial delata el SO de origen (Linux ≈ 64, Windows ≈ 128). Un TTL muy bajo al llegar puede significar muchos saltos — útil para detectar rutas anómalas o tráfico de botnets. Los atacantes usan traceroute (explotando TTL) para mapear la red en fase de reconocimiento.
